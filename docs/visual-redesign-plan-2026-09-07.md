# bing-ui 外观改造方案与可行性评估

日期：2026-09-07。状态：第一批真实组件试做已完成，待评审外观方向。本文保留改造前的审计与规划，并在末尾记录实施范围和验证结果。

## 结论与范围

建议将默认外观调整为「中性灰黑、紧凑尺寸、轻边框、局部磨砂」，沿用现有 Vue 组件和 GSAP 交互。技术可行性高，全库工作量中等偏大，主要成本在逐组件统一视觉和尺寸回归。

本轮用户认可现有交互，要求改变基础外观与大小。因此液态悬停、文字反馈、弹层错峰入场、卡片翻转、拖拽排序和转场的行为、触发规则、时序均作为保留基线。外观试做通过后再讨论需要单独微调的动效；不会将「简约」直接解释为取消这些能力。

本方案只提取 ultimate-WebGIS 的视觉语言，不迁移其 React、Radix、Tailwind 组件实现，也不新增 shadcn 运行时依赖。

## 建议视觉规格

以下数值为首轮试做起点，需结合实际组件确定。

### 尺寸与排版

| 项目 | 建议 |
| --- | --- |
| Button xs / sm / md / lg / xl | 28 / 32 / 36 / 40 / 44px，保留现有 size 名称 |
| Input / Select / DatePicker 等 sm / md / lg | 32 / 36 / 40px，默认 md |
| 单行菜单项 sm / md / lg | 28 / 32 / 36px；有说明或自定义内容时允许更高 |
| Table 单行行高目标 sm / md / lg | 32 / 40 / 48px，内容决定最终高度；含编辑控件时预留上下空间 |
| 字号 | 正文和默认控件 14px，紧凑控件 13px，辅助文字 12px，面板标题 15–16px |
| 图标 | 默认 16px，大号约 18px，沿用 BingIcon 的规范化职责 |
| 圆角 | 基础控件约 6px，菜单 8px，卡片约 10px，弹窗约 12px |
| 间距 | 4 / 8 / 12 / 16 / 24px；表单项间距约 16px，面板内边距 16px |

不对组件使用整体 `scale()` 来缩小。高度、字体、图标、标签、滚动区域和点击区域各自调整。移动端或粗指针模式保留约 44px 的有效触摸区域，输入文字考虑 16px，避免照搬桌面的紧凑规格。

### 颜色与材质

- 浅色起点：主文字和主按钮 `#18181b`，次文字 `#3f3f46`，辅助文字 `#71717a`，边框 `#e4e4e7`，实色底 `#ffffff`，悬停底 `#f4f4f5`。
- 深色起点：炭灰画布、深灰面板、浅色文字与主按钮；独立配置对比度、边框和透明度。
- Primary 使用中性实色；Secondary 使用浅灰底；Tertiary 使用细边框；Ghost 保持轻量。保留 danger / success / warning 的语义颜色。
- 品牌粉色可用于品牌标识或小面积强调。灰色选中态同时使用勾选、边线或文字区分，焦点要清晰。
- 普通表单控件和数据表格以实色为主；Popover、DropDown、浮动 Card、Dialog 面板适合磨砂。
- 磨砂试做参数：浅色底色不透明度约 0.82–0.90，深色约 0.90–0.94，模糊 12–20px，饱和度 1–1.1。参数不代表所有背景上都自动满足对比度要求。
- 采用单层带透明度的面板底色。避免继续用多层白色渐变叠加，再叠一个 `glassOpacity`；当前 Card 就存在这类情况，导致配置值与实际透光观感不一致。
- 毛玻璃不重复加到每个菜单项、每个表格单元格。嵌套弹层及 Dialog 遮罩分别判断是否需要模糊，验证合成与文字清晰度。
- 禁用毛玻璃或不支持模糊时应有可靠实色底。改造前 `glass: false` 在公共工具中返回 0.96 不透明度，第一批已统一为 1，并为首批磨砂组件补充不支持模糊时的实色回退。

## 技术落点

当前有 33 个组件目录，包含部分无视觉容器和转场组件，并非 33 个都要同等重写。

1. **主题基础**：调整 `src/theme/tokens.css`、`light.css`、`dark.css`。沿用 `light / dark / system`，补充字体、密度、表面和圆角的用途变量。深色与 system-dark 必须同步。
2. **语义梳理**：区分主要操作、普通悬停/选中、品牌色、状态色。保留现有 CSS token 名称和粉/蓝色阶定义，避免将名字为 pink 的色阶直接改为灰色。旧语义 token 可映射至新体系，减少接入方改动。
3. **组件样式**：迁移组件内独立的字体、边框、阴影、圆角、尺寸数值。仅改主题变量无法消除局部渐变、粗字重或专属尺寸。
4. **现有磨砂工具**：复用 `src/utils/glass.ts` 及组件现有 `glass / glassBlur / glassOpacity / glassSaturation` 接口。先梳理默认值与变量优先级，不另造一套并行材质 API。显式 prop 应覆盖主题默认。
5. **表单尺寸继承**：保留 `useFormControl` 中组件 prop → FormItem → Form → md 的尺寸优先级。
6. **动画保留**：`src/motion/liquidHover.ts` 已将动画节奏与组件配色分开；Select/TreeSelect 共用 `selectPanelMotion.ts`。先沿用原时间线，仅校准新尺寸下的裁剪、原点、选中反馈可见度。不要为了外观统一重新实现动画。
7. **Storybook**：先建立一张中文综合试做页，同时展示表单、菜单、卡片、表格和状态。默认背景中性；另有内容背景检查玻璃。大面积粉蓝背景会持续影响对外观的判断，需同步调整。

不建议仅用一份全局覆盖 CSS 堆叠 `!important`；正式实现应回到主题和组件样式。也不建议首轮长期维护两套完整皮肤，当前阶段优先集中打磨新默认外观。

每阶段只完成该批范围，不先完成整库再判断设计方向。需要交互逻辑调整时运行 `pnpm test:run`，并补充有价值的浏览器验证；涉及库 API 或构建入口再运行构建。所有影响界面的阶段均用无头 Playwright 检查对应 Storybook 页面。按项目约定不运行视觉快照回归、不更新快照。

粗略工作量：代表组件试做约 1–2 个专注开发日；全库统一及回归约 5–8 个专注开发日，前者包含在后者内。这是基于当前代码的范围估计，不是交付承诺；首轮试做后应修正。

## 主要风险与处理

| 风险 | 已有证据或触发条件 | 处理 |
| --- | --- | --- |
| 虚拟列表尺寸错位 | Select 的 `virtualItemHeight` 默认 44，规范化硬下限为 40；普通项还有独立 40 / 36px 规则 | 默认行高、CSS 与 JS 计算使用同一来源，保留显式自定义值；验证首尾项、键盘滚动、滚动定位 |
| 弹层定位和标签溢出变化 | 控件变小、字体变轻后文字宽度、锚点和可见标签数量改变 | 覆盖四方向展开、长标签、多选换行、边界翻转、表格内浮层 |
| 文案动画被裁切 | 按钮文字跳动使用额外内边距与位移 | 单独验证 textEffect 的高度、裁剪与点击区域，保留原触发和节奏 |
| 透明表面性能与可读性 | 内容背景、嵌套模糊、滚动、卡片 3D 变换可能同时存在 | 避免逐项模糊和动画 blur；检验实色退化、浅深主题、运动过程文字清晰度 |
| 主题作用域 | 弹层 Teleport 到 body，现有主题要求作用在 html | 延续 document 级主题；首轮不承诺任意局部主题可跨 Teleport 自动继承 |
| 样式兼容 | size 名称不变但实际高度改变；外部覆写可能依赖旧 CSS | 视为有意的视觉兼容性变化，发版时明确尺寸映射并提供迁移说明 |
| 明确颜色的变体 | 例如 Card 的 `sky` 等名称具有具体颜色含义 | 保留显式颜色变体与能力，新默认样式采用中性底；不把 sky 悄悄解释为灰色 |

建议采用一次明确的外观升级版本。是否提供旧外观兼容入口，应在检查下游使用情况后决定；不能把「调用 API 不变」等同于「视觉无破坏」。

## 第一批实施结果

经用户确认，对 Button、Input、Select、Card、DropDown 及菜单项进行真实组件样式改造，同时更新共享主题与尺寸变量。组件的 props、emits、slots 保持原有接口，GSAP 时间线与触发方式沿用原实现。

- 默认控件高度从 38 / 44 / 52px 调整为 32 / 36 / 40px；按钮额外保留 28px 的 xs 与 44px 的 xl。控件圆角 6px，弹层 8px，默认卡片 10px；降低文字粗细和阴影强度。
- 默认主色改为中性灰黑；次按钮使用灰色表面，危险、成功和警告状态继续保留语义颜色。显式品牌色阶仍可使用。
- 首批磨砂组件使用主题默认值：浅色底色不透明度 0.86，深色 0.92，模糊 16px，饱和度 1.05；显式玻璃参数优先。普通表单控件采用实色底。
- Select 的单行选项高度为 28 / 32 / 36px，普通列表和虚拟列表共享尺寸来源。自定义内容默认增加 16px 空间，可显式设置 `virtualItemHeight`。详情浮层中的说明不增加普通行高，显式 44px 虚拟行高继续生效。键盘定位已计入虚拟列表顶部留白，末项可完整滚入视口。
- 共享高度也影响其他表单组件。本轮仅对 TreeSelect、DatePicker、ColorPicker 的箭头和清空区域做必要的高度适配，避免小尺寸被内部按钮撑高或越界；这些组件的专属视觉仍待下一批调整。

真实组件组合页位于 `.storybook/VisualRefresh.vue`，通过 `src/components/VisualRefresh.stories.ts` 注册到 Storybook 的 **Design / 外观试做**：

- 「图层工作区」：内容背景上的磨砂卡片和菜单，可搜索图层、编辑名称、选择几何类型、保存设置、打开子菜单，并体验卡片长按翻转。
- 「实色表面」：关闭磨砂，检查基础边框与层级。
- 「紧凑尺寸」：32px 控件与 28px 单行选项；Controls 可切换 sm / md / lg。

## 第一批反馈优化

> 更正：本节记录早期实现。其「输入建议」属于对需求的误解，已按后续反馈撤回，包括相关 API、Storybook 示例及图层名称候选列表。当前 Input 默认设置 `autocomplete="off"` 关闭历史提示，具体限制见 README。

根据用户随后提出的四点反馈，完成以下调整：

1. `BingInput` 新增 `number` 类型及 `min` / `max` / `step`，沿用原生数值输入和步进语义。`v-model` 扩展为字符串、数字或初始空值；数字类型输入时输出数字，清空返回 `''`，文本类型及 `input` / `debounced-input` 的字符串行为保留。接入方手写的 `update:modelValue` 回调需接受 `string | number`。
2. Button、Select、DropDown 与输入建议采用独立的波纹色彩变量：浅色以白色高光和低透明度淡蓝铺开，深色降低高光强度。移除次按钮和选项上额外叠加的深灰覆盖层，保持文字清晰；动画节奏沿用共享液态悬停工具。
3. DropDown 主菜单与子菜单复用 Select 的方向位移、轻缩放和逐项错峰时间线。处理开关中断、禁用、减少动态效果和卸载清理。子菜单键盘事件跨 Teleport 回传；入场尚未完成时按右方向键，显示后再转移焦点，避免聚焦隐藏菜单项。
4. 用户确认「输入提示」是浏览器保存的历史或自动填充列表。新增可选 `suggestions`，以组件自己的磨砂面板展示业务候选，支持筛选、方向键、Enter、Escape、禁用项、自由输入和中文输入法。未启用时保留原生关联列表与 ARIA 属性；在 Dialog 内正确处理焦点与 Escape 的弹层顺序。它不会读取浏览器保存的数据；浏览器原生弹层也不会被此组件直接换肤。启用建议时默认 `autocomplete="off"`，显式设置优先；该提示仍可能被浏览器忽略。

### loading 保留文字并循环 jump

Button 的 loading 状态改为保留文案和前后图标，文字自动循环逐字 jump，沿用现有 `textJump` 系列参数。结束后恢复配置的 none / shine / jump 及触发方式，按钮本体与图标位置保持稳定；纯图标按钮继续使用加载图标。按钮仍不可点击且保留 `aria-busy`，显式禁用或减少动态效果时显示静态文字。

共享 BingAnimatedText 让 Vue 始终保留原始文案与布局，SplitText 只操作隐藏于辅助技术的装饰副本；副本设为 inert 并移除重复 ID。这样加载中更新文案、切换文字效果或结束 loading 时不会破坏 Vue 的文本节点，也能准确清理循环动画。按钮所有状态使用一致字距，避免英文拆字导致宽度变化。表单错误描述测试同步改为核对可访问文案，不将装饰副本计入文字。

### 数字箭头与原生补全需求更正

数字输入原先使用浏览器原生步进箭头，其深色绘制包含独立背景块。现隐藏原生箭头，使用随主题着色的透明底 SVG 按钮，保留原生数字输入、范围校验与键盘操作。点击和长按调用原生步进方法，`step="any"` 时从当前数值加减 1 并遵守范围；松开、移出、取消、窗口失焦、切换禁用或只读、组件卸载时停止连续步进。

用户需要确认浏览器保存的历史输入或自动填充弹层能否换肤。此前新增业务候选列表属于误解，已撤掉 `suggestions` / `suggestionLimit` / `suggestion-select`、对应类型、列表控制器、样式及 Storybook 示例，图层名称恢复普通输入框。原生弹层由浏览器界面绘制，页面 CSS 无法控制；此前普通 Input 未设置 `autocomplete="off"`，所以原生提示仍会出现。按「改不了就算了」保留原生功能，继续透传显式 `autocomplete`，不默认关闭。README 已说明原生弹层与 `:autofill` 的区别及 `off` 可能被忽略的限制。
